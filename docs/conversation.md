# 第 4 题二档「桌宠」：关键对话摘录

> 项目：Electron 桌面宠物
> 会话分享链接：待填写

## 摘录一：先把范围定住，而不是直接要完整项目

### 当时的问题

```text
我在参加一个大学实验室的编程笔试，需要开发一个桌面宠物（桌宠），要求：
1. 常驻桌面，有界面；
2. 支持点击、拖拽、说话、走动；
3. 使用 Electron + HTML/CSS/JavaScript；
4. 运行环境是 Windows 11，Node.js 24；
5. 不允许使用 Cursor、Copilot 之类的 agent 工具代写，我会手动把代码粘贴成文件；
6. 项目结构要规范，代码要模块化，方便我向老师解释。

请先不要写代码。请给我功能清单、文件职责、窗口方案，
并解释拖拽和走动分别适合怎么实现。
```

### 为什么这样问

我一开始只知道题目要求“有界面、可交互”，但不知道桌宠应当怎样拆分模块。如果直接让 AI 写完整项目，最容易拿到一个能跑但看不懂的大文件。所以先限定技术栈和运行环境，再要求 AI 只做方案设计，不输出代码。这样我可以先判断哪些是核心功能、哪些可以延后，后面每轮改动的范围也容易控制。

我也明确写了“我会手动粘贴文件”，因为题目不允许使用能直接读写项目的 agent 工具。提前把这条限制说出来，AI 才不会给出依赖自动改文件的流程。

### AI 给出的方向

AI 建议使用 Electron 的 `BrowserWindow`：`transparent: true` 做透明窗口，`frame: false` 去掉标题栏和边框，`alwaysOnTop: true` 让桌宠常驻在最上层。交互放在渲染进程，窗口位置和系统级操作放在主进程，两边用 IPC 通信。

最终代码沿用了这个分工：`main.js` 负责窗口、移动和状态保存，`pet.js` 负责表情、气泡和鼠标事件。项目因此拆成几个文件，没有把所有逻辑塞进一个入口。

### 我的判断

方案可行，但方案阶段没有交代透明窗口的边界：默认情况下窗口会占住整个矩形区域，鼠标经过透明部分时也会被它接住，下面的桌面图标就点不到。这成为下一轮需要重点解决的问题。

## 摘录二：先跑通最小窗口，再叠加交互

### 当时的问题

```text
按刚才确定的方案，帮我搭建最小可运行版本。

请分文件给出完整代码，路径使用以下结构：
package.json
src/main.js
src/preload.js
src/renderer/index.html
src/renderer/style.css
src/renderer/pet.js

要求：
1. 窗口 220x220，无边框、透明、置顶、任务栏不显示；
2. 渲染进程不能直接使用 Node API，contextIsolation 必须开启；
3. 先实现静态显示一个圆角宠物形象，不需要图片素材；
4. package.json 加上 npm start 脚本；
5. 说明在 PowerShell 里从零安装和启动的命令。

每个文件单独给出，不要省略代码。
```

### 为什么这样问

第一轮确定方向后，我没有马上要求加入随机走动和持久化。桌宠的问题通常同时来自窗口配置、页面加载和进程通信，如果一次叠加全部功能，遇到白屏或窗口不显示时，很难判断错在哪一层。这一轮只要求窗口能出现、宠物能看见，并强制 AI 按路径给出完整文件，方便逐个核对。

我特意要求 `contextIsolation: true`，并禁止渲染进程直接使用 Node API。Electron 的旧教程常建议 `nodeIntegration: true`，但那样页面脚本可以直接访问文件系统，是常见安全错误。提前把这条写进需求，可以避免后面返工。

### 实际结果与后续发现

窗口能够正常显示，说明 Electron、窗口配置和页面加载这一层已经跑通。后续实现沿用了这一轮的结构，只增加 `state-store.js` 来负责持久化。

这一轮也说明了透明窗口还需要额外的鼠标穿透处理：宠物轮廓之外的区域应当允许点击落到桌面，而不是整块 220×220 窗口都拦截鼠标。

## 摘录三：拖拽和单击必须能同时成立

### 当时的问题

```text
现在实现桌宠交互，保持上一轮的文件结构：

1. 按住宠物可以拖拽整个窗口；
2. 单击宠物时切换一个“被摸到”的开心表情，并在 1 秒后恢复；
3. 拖拽和单击要能区分：拖动超过 5 像素算拖拽，不触发单击；
4. 窗口位置要限制在屏幕可见范围内；
5. 所有鼠标事件只在宠物区域监听，不拦截整个桌面的点击。

请给出需要修改或新增的完整文件，
并说明事件监听器绑定在哪个元素上、IPC 数据怎么从渲染进程传到主进程。
```

### 为什么这样问

只写“支持点击和拖拽”不够，因为这两个动作在鼠标事件里天然冲突：按下后移动是拖拽，按下再原地松开是点击。如果两套逻辑各自监听 `mousedown`，每次拖拽都会顺带触发一次“被摸到”。

所以我给了明确阈值：位移超过 5 像素才算拖拽，否则松开时才算点击。这样 AI 不能含糊地写两个独立监听器，必须维护“已按下、是否正在拖拽、起点坐标”这些状态。最终 `pet.js` 正是按这个思路实现的：按下时记录 `startX`、`startY`，移动时累计位移，松开时根据 `dragging` 决定调用 `dragEnd` 还是 `handleClick`。

我同时要求说明 IPC 的数据方向。窗口移动不能由渲染进程直接完成，必须把屏幕坐标传给主进程，由主进程调用 `win.setPosition`。这段数据流说不清，即使程序能跑，也很难回答题目要求的“三个关键模块”说明。

### AI 方案中需要修正的地方

一个常见错误是用 CSS `-webkit-app-region: drag` 实现拖拽。它能让窗口整体拖动，但会把鼠标事件交给系统窗口管理器，页面里的点击监听收不到事件，宠物无法响应“摸头”。最终实现没有用它，而是用普通鼠标事件，再通过 IPC 驱动窗口移动。

另一个错误是只处理拖拽、不限制窗口边界。最终代码用 `clampToWorkArea` 读取当前屏幕的工作区，把窗口限制在可见范围内，避免宠物被拖到屏幕外后找不回来。

### 验证方式

实际运行时分别检查：

- 原地短按再松开，气泡显示“第 N 次被摸到～”，计数增加；
- 按住后移动超过 5 像素，窗口跟随鼠标移动，松开不增加点击计数；
- 把宠物拖向屏幕边缘，窗口停在可见区域内；
- 鼠标移到宠物轮廓外的透明区域，点击可以落到桌面，不被窗口挡住。

## 答卷用简版

第一轮，我没有直接要完整代码，而是先限定 Electron、Windows 和“手动粘贴代码”的约束，要求 AI 只给功能拆分和窗口方案。这样做的原因是避免拿到不可维护的大项目，同时确保方案不依赖 agent 工具。

第二轮，我要求先做最小可运行窗口，并指定 `contextIsolation: true`、禁止渲染进程直接访问 Node。这样做的原因是一次只验证一层，先确认窗口和页面能加载，再叠加拖拽、走动和持久化，出问题时更容易定位。

第三轮，我要求用 5 像素阈值区分拖拽和点击，并说明 IPC 的数据流。这样做的原因是两个交互会争抢同一组鼠标事件。最终没有采用会吞掉点击的 `-webkit-app-region: drag`，而是记录起点、累计位移，再由主进程移动窗口并限制窗口边界。
